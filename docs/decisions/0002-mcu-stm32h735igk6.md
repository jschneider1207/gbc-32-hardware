# 0002: MCU is the STM32H735IGK6

- Status: Accepted
- Date: 2026-11-21

## Context
The board needs an STM32H7. The firmware is written for the Cortex-M7 and
developed on a NUCLEO-H753ZI. The MCU has to drive:

- a 16-bit FMC SDRAM for the active ROM (ADR 0001);
- 8-bit eMMC over SDMMC;
- SAI audio;
- USB;
- a display, still undecided (FMC parallel or LTDC);
- about 22 GPIO.

Constraints:
- **Size:** it has to fit a handheld, so a small package is wanted on the
  final board.
- **Assembly:** one device, assembled by JLCPCB, so BGA and extended parts
  are fine.
- **Power:** battery-powered, so core power efficiency matters.

Internal RAM and flash no longer drive the choice. The ROM lives in SDRAM,
so internal RAM only has to hold emulator state (~200 KB) and buffers.
Flash only has to hold the firmware: a few hundred KB is the estimate, and
nothing is built yet. What matters is:

- CPU clock;
- L1 data cache size, because every ROM read from SDRAM goes through it;
- an on-chip SMPS;
- package size;
- whether it can be bought.

### Options considered (the 13 STM32H7 lines)

Line summaries come from ST and distributor overviews, except where a
datasheet is cited. ST's series selector page wrongly describes the
H745/755 as single-core; the line's own pages say Cortex-M7 + Cortex-M4.

| Line | Verdict | Reason |
|---|---|---|
| **H725/735** | **Chosen** | 550 MHz, on-chip SMPS, 32 KB + 32 KB L1, 1 MB flash, 564 KB RAM, UFBGA176+25 at 10×10 mm, in stock at JLC |
| H743/753 | Runner-up | Same family as the dev board (RM0433) and 480 MHz, but LDO only (DS12117 lists only an LDO), 16 KB + 16 KB L1. The only one JLC stocked was the 100-pin VIH6, too few pins for SDRAM. The H743IIK6 is only available through global sourcing. |
| H723/733 | Fallback | Same core and cache as the H725/735, without the SMPS |
| H7R3/7S3, H7R7/7S7 | Reserve | 600 MHz, but only 64 KB of boot flash, so it needs an external boot flash and a different boot model. Only worth it if Stage 2 shows the CPU is short. The H7R7/7S7 GPU is no use for integer scaling. |
| H745/755 | Rejected | Dual-core (M7 480 MHz + M4 240 MHz). See below. |
| H747/757 | Rejected | Dual-core like the H745/755. Its only draw is a MIPI DSI display interface, which we don't need. |
| H7P4/7P5 | Rejected | Not available. Also unconfirmed SDRAM support and only 320 KB RAM. |
| H7A3/7B3 | Rejected | 280 MHz is too large a CPU cut before the emulator has proven its speed. Its large RAM no longer helps. |
| H750, H730, H7B0 | Rejected | Value lines with 128 KB flash, which forces external-flash boot. The H7B0 also runs at only 280 MHz. |
| H742 | Rejected | Cut-down H743 with no advantage over it |

**Dual-core was rejected on its merits.** Only pixel rendering could move to
the M4: the M7 would log writes to VRAM, OAM, palettes and scroll registers,
and the M4 would draw from that log. These are estimates, not measurements:

- If rendering is ~30% of M7 time at 480 MHz, the M4 needs about 212 of its
  240 MHz (M4 ~3.4 vs M7 ~5.0 CoreMark/MHz, from memory). It has no L1
  cache, and every write crosses between cores.
- Cache coherency between the cores, two firmware images and a dev-board
  change would cost more than the ~5–15% gain.
- The H725/735 gets similar headroom from its clock and cache alone.

## Decision
The MCU is the **STM32H735IGK6**: UFBGA176+25, 1 MB flash, temperature
range 6 (−40 to 85 °C). The H735 is the H725 plus crypto/hash blocks, which
we don't use. We chose it over the H725 only because JLC had it in stock.
The same package goes on both the prototype and the refined board, so the
refined board isn't the first to try the BGA fan-out. The pin map is the
same either way.

### Checked against the datasheets
DS13312 Rev 4, RM0468 Rev 3, ES0491 Rev 9. These are in `datasheets/`.

- **Clock** (DS13312 Table 13):
  - CPU: 520 MHz at VOS0, 550 MHz with `CPU_FREQ_BOOST`. That bit is in
    SYSCFG_UR18 (RM0468 §12.4.26) and turns off ECC on ITCM/DTCM.
  - AXI/AHB: 275 MHz maximum.
- **SMPS at full speed** (DS13312 Table 14): VOS0 is allowed with the core
  supplied directly by the SMPS (min VDD 2.2 V, max TJ 105 °C). We get the
  SMPS power saving without giving up clock speed.
- **Memory** (DS13312 §2): 32 KB I-cache and 32 KB D-cache. 564 KB RAM: 128 KB
  DTCM, 64 KB ITCM, 192 KB shareable between ITCM and AXI, plus further
  AXI/AHB SRAM.
- **Package** (DS13312 §7, Table 138): UFBGA176+25, 10×10 mm, 0.65 mm pitch.
  Table 138 gives example PCB design rules for the fan-out.
- **SDRAM clock** (DS13312, SDRAM timings): FMC_SDCLK max is 95 MHz at
  2.7–3.6 V with 20 pF, about 190 MB/s peak on 16 bits. ADR 0001 assumed
  ~100 MHz; the conclusion is unchanged.

### Errata (ES0491 Rev 9, silicon revisions A and Z)

| Erratum | Effect | Action |
|---|---|---|
| §2.7.3 | Unaligned reads from the FMC region not supported | Firmware reads the ROM byte by byte (ADR 0001 update) |
| §2.7.1 | Two dummy reads after each SDRAM burst | Harmless; costs a little bandwidth |
| §2.9.1 | SDMMC doesn't check end bits | Harmless; data is still correct |
| §2.16.1 | Window watchdog fails below 2.7 V at VOS0/VOS1 | Fine on the planned regulated 3.3 V rail. Another reason not to run VDD straight off the battery. |
| §2.2.5 | USB DFU doesn't work with readout protection level 1 | We won't enable readout protection |
| §2.1.1 | Speculative linefill to an address the MPU would fault | Note for the firmware's MPU setup |

Three H753 errata (ES0392 Rev 16) don't appear for this part:
- §2.2.21: 480 MHz unavailable on old silicon;
- §2.1.1: data-cache write-through corruption;
- §2.2.32/33: backup domain (RTC) not reset after a power cycle.

### Pin fit (draft, from DS13312 Tables 8–9)
Cross-checked against ST's STM32_open_pin_data XML; no disagreements found.

| Display option | Fits? | Spare GPIO |
|---|---|---|
| FMC 16-bit 8080 LCD sharing the SDRAM data bus, eMMC on SDMMC1 | Yes | 35 |
| LTDC RGB565, eMMC on SDMMC2 | Yes | 20, minus ~3 if the panel needs SPI setup |

With LTDC, 8-bit SDMMC1 can't be used: LTDC_HSYNC and LTDC_G6 exist only on
PC6/PC7, which are also the only pins for SDMMC1_D6/D7.

Other placements in the draft:
- SDRAM bank 0 control (SDNE0/SDCKE0) on the PC2/PC3 digital pads;
- SAI1 on PE2–PE6;
- I2C1 on PB6/PB7;
- USART3 log on PB10/PB11 (also a bootloader port);
- USB on PA11/PA12;
- power button on PA0 (WKUP1);
- battery sense on the analog-only PA1_C.

No EXTI line collisions in either option. The full draft pin map gets
recorded in `docs/firmware-interface.md` once the display option is chosen.

## Consequences
- **Firmware (`../gbc-32`).** The custom board needs its own platform layer.
  This is recorded in that repo's README Stage 3 and `docs/architecture.md`
  "Targets". The differences from the dev board:
  - RM0468 instead of RM0433;
  - SMPS supply configuration at boot;
  - a different RAM layout and larger caches, so the linker script and
    Stage 2 tuning get redone;
  - ROM in SDRAM, read byte by byte;
  - new drivers for eMMC, USB upload, display and audio.

  Stage 2 on the NUCLEO-H753ZI is unchanged.
- **PCB:** 6 layers (ADR 0001); 0.65 mm-pitch BGA fan-out. Because nothing
  on a BGA can be probed, the board gets:
  - test points on SDCLK, the SDRAM control lines, NRST and BOOT0;
  - a pull-down on BOOT0 (dedicated ball C5);
  - keep PC2/PC3 analog switches open (SYSCFG_PMCR PxySO, RM0468 §12.4.1,
    reset value 1).
- **Power:** use the on-chip SMPS in direct mode at VOS0. Its external
  inductor and capacitors come from DS13312 Table 16 and ST's
  hardware-development application note for this family (to download).
- **Sourcing:** JLC had 7 in stock on 2026-11-21. Reserve about 4–5 in the JLC
  parts inventory: 2 for the prototype, 2 for the refined board, 1 spare.
- **Follow-ups:**
  - Confirm the lifecycle status (active, not NRND) on ST's product page.
  - Download the H72x/73x hardware-development application note, and the
